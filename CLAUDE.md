# Case-study maintenance

- This repository presents selected architecture and evidence; it is not a booking client.
- Write public content in English. Keep the README concise and client-facing.
- Treat source projects as read-only. Never run their tests, builds, or live commands here.
- Keep design, implementation, historical validation, and present checks separate.
- Bind factual claims to the source catalogue and a dated evidence summary.
- Never upgrade a historical result into current product readiness.
- Preserve UNKNOWN and the distinction between remote results and local occupancy.
- Plain status is read-only; explicit verification/refresh branches have separate semantics.
- Keep Direct and HouBu explicit choices; payment remains manual.
- Use stable diagram identities in diagrams/node-registry.yaml.
- Edit Mermaid sources and regenerate exports; never hand-edit SVG output.
- Keep all public links relative and usable without access to the private project.
- Never include credentials, passenger details, order identifiers, private paths, or raw responses.
- Code excerpts must state whether they are verbatim, adapted, or pseudocode.
- Do not add a permissive license, commit, push, or publish without explicit authorization.
- Local checks: node scripts/check.mjs; renders: bash scripts/render-diagrams.sh.
